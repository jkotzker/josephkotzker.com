# Critique of the page set — 034, 035, 039, 040, 041, 042, 044

Date: 2026-10-02

Scope: the seven current pages built on the adopted home page (031): home 034, blog index 035, résumé 039, 404 040, post 041, projects 042, podcasts 044. The focus is cross-page coherence, which Joseph set as the guiding principle. Measured in the browser over localhost at 1059px wide, in both colour schemes. Where a finding is a measurement, the number is given.

Already verified and not repeated below: the shell (sidebar, column, footer, page-title style) is identical on all seven pages; heading levels never skip on any page; every text colour on every page passes WCAG AA in both schemes (lowest 4.53:1 light, muted sidebar text; 5.17:1 dark). Syntax colours in code blocks reach at least 5.54:1.

## Slop tells

- (041, code blocks, syntax colours) The highlighting uses Expressive Code's default GitHub light/dark themes: red keywords, purple types and blue strings. Nobody chose those colours, and they are the only hues on the site besides the link blue. Joseph's palette rounds ended with "no warm accent colour". A muted or two-tone theme, or the link blue plus the existing greys, would keep code in the site's palette. The choice belongs to the integration config, not the post.
- (all pages, body face) Not a tell here. The system serif was flagged in critique 001, and Joseph has since chosen "simple system faces" himself (`direction.md`).
- None found otherwise. There are no gradients, glass, feature grids or decorative blobs, and every icon comes from the two chosen outline sets.

## Coherence breaks

- **(035 / 034 / 041 / 039, dates) Four date formats in one site.**
  - The blog index (035) uses "Sep 28" under year headings.
  - The post byline (041) uses "Sep 28, 2026".
  - The résumé (039) uses "Month Year – present".
  - The home lists (034) still show "Sample date".
  - One rule for dates in lists and one for bylines would settle it. Choosing them is a Part 3 / hand-off decision, but the format needs deciding before content is entered.
- **(041, `p.meta.byline > time`) The post's date renders smaller than every other date.** It is 14.9px against 16.56px in the lists. The `time, .meta { font-size: var(--text-small) }` rule shrinks the date twice, because the `<time>` sits inside a `.meta` paragraph (0.9 × 0.9 of the body size).
- **(035 `li time` vs 044 `.episodes .num`) Two different label columns for the same job.**
  - The blog list puts the date in a 6.5em column and lets long titles wrap back under it.
  - The episode list puts the number in a 3.5em column and indents wrapped lines so they clear it.
  - These are the same pattern (a muted label, then a link) built twice.
- **(041, code block titles) Two title treatments.** The titled editor block shows its file name as a tab above the box at top left. The terminal block shows its title centred inside a bar. Both come from Expressive Code's defaults: an editor frame for most languages and a terminal frame for shell. Forcing one frame style for every block would give a single treatment.
- **(041, code blocks) Corners and type that differ from the rest of the site.**
  - Frames have a 3px radius (`figure.frame`, `pre`), against the site's 2px (`--radius-focus`, image placeholder). The `borderRadius` override reached some parts but not the frames.
  - The "Copied!" message and the copy button render in Arial at 13.3px, a third typeface. Buttons do not inherit the page font.
- **(041, copy button focus) A different focus ring from every other focusable element.** Reached with Tab, the button shows the browser's default ring: auto style, 1px, light blue. Every link on the site uses the 2px link-colour ring offset by 3px (`a:focus-visible`).
- **(041, `.footnotes` + `footer`) Two hairline rules stacked within a few lines.** One rule closes the footnotes and the next opens the footer.
- **(034 vs 042, project names) The same entity behaves differently on two pages.** On the home page each project name is a link (034). On the projects page the name is a heading, with its links in a row below (042). The home list needs to follow 042: link to the project's section on `/projects`, or drop the link.
- **(all pages, footer) Duplicate RSS link.** The footer's "RSS" duplicates the sidebar's RSS entry on every page. Critique 001 noted this; it is still there.
- **(044, `.links`) RSS wraps alone onto a second line** at 1059px, with six links in the row. A lone entry reads as a separate item rather than part of the row.

## Placeholder copy

- (all pages) Visibly sample, as intended: post, project and role titles; dates; the image and headshot placeholders; `#` hrefs (Apple Podcasts, Spotify, YouTube, Overcast, every post and project link). None of it blocks judging the design. The `#` hrefs mean navigation between prototypes cannot be tested by clicking.
- (044, episode list) The titles are real (from the public feed), and they use a spaced hyphen as the separator ("The Fast and the Furious - A Kiss…"). Elsewhere on the site an em dash is used ("In Reverse — co-host"). Converting " - " to an en or em dash when the feed is read would match. This is content handling, not layout.

## Basic accessibility

- (all pages) Contrast passes AA throughout (see Scope). Heading levels never skip. Links show the site focus ring. Nothing animates.
- (041, footnote links) Small targets: the footnote marker measures 9 × 21px and the back-link "↩" 17 × 23px. These are conventional for footnotes and well under ~40px.
- (all pages, footer "RSS") 30 × 23px.
- (041, copy button) 32 × 32px. It stays invisible until the block is hovered or focused, then shows the browser-default ring noted above.
- (sidebar and `.links` rows) ~30px tall rows. This is the trade-off accepted at 029, and the link rows in 042/044 inherit it.

## The one thing to keep

The link row in `forks/042-projects-links.html` and `forks/044-podcasts-more-platforms.html` (`.links`): the sidebar nav's entries laid out inline, matching its colour, size, line height and hover (measured identical). It shows the anchor carries over into the reading column. Any later list of external links on the site (a post's "elsewhere" links, a résumé's contact row) should be generated "in the same style as the `.links` row in forks/042".
